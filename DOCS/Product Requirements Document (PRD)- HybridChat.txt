Product Requirements Document (PRD): HybridChat
Version: 1.0
Date: April 1, 2026
Product Owner: Ashish Sharma 
Target Platforms: Android, iOS, Web (Progressive Web App)
________________


1. Overview
HybridChat is a secure, hybrid messaging app that enables personal DMs, group chats, and broadcast channels using both Bluetooth (for local, offline communication) and internet (for remote messaging). The app prioritizes privacy, minimal server data storage, and end-to-end encryption.
________________


2. Objectives
* Enable seamless messaging in both online and offline environments.
* Ensure privacy: no message content stored on the server for Bluetooth messages.
* Support real-time availability detection (Bluetooth vs. internet).
* Provide a secure, encrypted, and user-friendly experience.
________________

4. Tech Stack
A. Backend
* Language: Node.js (TypeScript)
* Framework: Express.js
* Database: MongoDB (Atlas for cloud)
* Authentication: JWT, bcrypt
* Encryption: libsignal (Signal Protocol) for E2EE, OpenSSL for key management
* Real-time: Socket.io (for internet mode)
* API Documentation: Swagger/OpenAPI
B. Frontend (Mobile)
* Android: Kotlin, Android Bluetooth API, Retrofit for REST, WebSockets
* State Management: Jetpack Compose (Android), Combine (iOS)
* Encryption: Native libsignal bindings
C. Frontend (Web - PWA)
* Framework: React.js (Next.js)
* Styling: Tailwind CSS
* Bluetooth: Web Bluetooth API (Chrome/Edge only)
* Real-time: Socket.io-client
D. DevOps & Infrastructure
* Hosting: AWS EC2 or Google Cloud Run
* CI/CD: GitHub Actions
* Monitoring: Sentry, Prometheus
* Containerization: Docker, Kubernetes (if scaling)

7. Security & Encryption
A. Authentication
* JWT: Tokens expire in 24 hours; refresh tokens last 30 days.
* Password Hashing: bcrypt (12 rounds).
* Rate Limiting: 100 requests/minute/IP.
B. End-to-End Encryption
* Key Exchange: Users exchange public keys during registration/first contact.
* Message Encryption:
   * 1:1 Chats: AES-256; key derived from sender’s private key + receiver’s public key.
   * Group Chats: Group admin generates groupPublicKey; all members encrypt with this key.
   * Bluetooth: Session key per Bluetooth session (stored in BluetoothSessions).
* Libraries: libsignal (Signal Protocol) for key management.
C. Data Privacy
* Bluetooth Messages: Only metadata stored on server.
* Internet Messages: Encrypted content stored; decryption keys never leave devices.
________________


8. Bluetooth Integration
* Scanning: App scans for Bluetooth devices every 30 seconds.
* Matching: Compares bluetoothMac with registered users.
* Direct Transfer: Uses RFCOMM sockets; no server involvement.
* Fallback: Auto-switches to internet mode if Bluetooth fails.
________________


9. UI/UX Requirements
* User Availability: Icons/colors indicate if a user is reachable via Bluetooth or internet.
* Message Status: Read receipts, delivery status (sent/delivered/read).
* Encryption Indicators: Padlock icon for encrypted messages.
* Offline Mode: Clear UI for Bluetooth-only messaging.
________________


10. Success Metrics
* Adoption: % of messages sent via Bluetooth vs. internet.
* Performance: Message delivery latency (target: <1s for Bluetooth, <2s for internet).
* Security: 0 breaches or unauthorized access incidents.
* User Satisfaction: CSAT score > 4.5/5.
________________


11. Risks & Mitigations
Risk
	Mitigation
	Bluetooth reliability issues
	Implement auto-fallback to internet mode.
	Key management vulnerabilities
	Use libsignal; regular security audits.
	Server scalability
	Use MongoDB Atlas; optimize indexes and queries.
	Battery drain
	Optimize Bluetooth scanning interval; use low-energy modes.
	________________
